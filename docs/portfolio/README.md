# Portfolio docs

Decision material for M Sal's three live web products (Rush Hour Planner, Heystacks, Benefits Advisor). These documents live in the Rush Hour Planner repo for convenience; they cover the whole portfolio.

| Document | What it is | Status |
|---|---|---|
| [`web-products-portfolio-brief-2026-09-21.md`](./web-products-portfolio-brief-2026-09-21.md) | Read-only **evidence** brief: traffic, cost, revenue and ops facts per product as of 21 Sep 2026, with source freshness and open gaps. No recommendations. | Snapshot — do not edit; add a new dated brief instead. |
| [`web-products-recommendations-2026-09-21.md`](./web-products-recommendations-2026-09-21.md) | **Recommendations** built on the brief: per-product keep / grow / monetise-first / mothball / sunset call, 30-day actions, risks, kill-criteria, portfolio sequence, and the missing data that would change each call. Facts are cited from the brief; derived arithmetic and judgment are labelled. | Decision input — revise as gaps close. |

Conventions:

- One dated brief + one dated recommendations doc per review cycle. Keep facts and judgment in separate files.
- Numbers not in the brief are marked **Derived** (arithmetic on brief numbers) or **Judgment** (estimate/opinion).
- Nothing here changes application code, dependencies, or Vercel configuration.
